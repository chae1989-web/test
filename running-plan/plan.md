## 훈련 방법론: NSM (Norwegian Singles Method)

- **하드 세션 배치 원칙(2026-07-17 변경, 요일/주 단위 리셋 폐지)**: 하드 세션(NSM-S/M/L + 롱런, 총 4종)은 특정 요일에 고정되지 않고 **요일과 무관하게 "하드 하루 → 이지런 하루"의 2일 주기가 끊김 없이 반복**된다. 한 하드 세션이 끝나면 다음 하드 세션 전까지 반드시 이지런 하루가 낀다(주가 바뀌어도 주기는 리셋되지 않고 이어짐). 하드 세션 종류의 순서는 **S → M → L → 롱런 → S → M → L → 롱런 → ...** 순환. 이 주기의 기준일(cycle day 1, 하드)은 **2026-07-13(월)**이었으나, **2026-07-19(사용자 요청, 예외 1회)**: 7/19 롱런이 목표 12km 중 9.01km(75%)만 완주해 실제 부하가 낮았다고 판단, 다음 하드 세션(NSM-S)을 이지런 버퍼 없이 바로 다음날(7/20)에 배치 — 원칙상 하드-하드 0일 간격 금지 규칙의 **의도적 1회 예외**. 이후 주기는 정상적으로 재개되어 새 기준일은 **2026-07-20(월, S)**이 된다. 예: 7/19(롱런)-**7/20(S, 예외 0일 간격)**-7/21(E)-7/22(M)-7/23(E)-7/24(L)-7/25(E)-7/26(롱런)-7/27(E)-7/28(S)-... 데일리 루틴은 매일 이 주기를 기준으로 다음 하드 세션 종류와 날짜를 계산해 빈 구간을 채우되, 이런 예외적 사용자 요청이 있으면 그때그때 반영하고 이후 주기는 그 지점부터 다시 정상 간격으로 이어간다.
- 주간 구성: 이지런 약 75% + sub-threshold 약 25%. 여유 있을 때는 **sub-threshold 세션 3회(short+mid+long, 매주 세 포맷 모두 함께) + 롱런 1회 = 워크아웃 4회**, 나머지는 완전 이지런/휴식
- **포맷은 단계별로 교체하는 게 아니라 매주 3개 다 돌리는 것이 원칙.** 각 포맷의 역할이 다름 — short(3~4min)는 역치 부근 회전율/스피드, mid(6~8min)는 중간 지속시간, long(10~12min)은 지속적 유산소 압박(레이스 특이성 가장 높음, 10K/HM 완주력과 직결)
- **세션이 3개가 아니라 2개만 가능할 때(회복 저조 등)는 short + long을 유지하고 mid를 뺀다** — short/long이 스펙트럼 양끝을 담당해 둘만으로도 폭넓은 자극이 되고 mid가 가장 먼저 생략 가능
- 퀄리티(워밍업/쿨다운 제외) 총 시간은 **주간 총 볼륨의 20~25%가 기본**, 볼륨이 크거나 훈련 연차가 쌓이면 **최대 25~30%까지 확장 가능**
- 인터벌은 **시간 기준**: `3min x 8~10rep` / `6min x 4~5rep` / `12min x 2~3rep`. **반복 사이 휴식은 조깅이 아니라 걷기(완전휴식도 가능)로 표기하며, 포맷별로 길이가 다르다(2026-07-15 변경) — short 60s / mid 90s / long 120s** (인터벌 길이가 길수록 회복에 필요한 휴식도 늘어난다는 원칙)
- VO2max/전력 인터벌은 최소화, 레이스 임박 구간에서만 목표 페이스 감각용으로 짧게 포함
- 이지런은 진짜 이지(HR 캡)로 철저히 통제 — sub-threshold 세션의 질과 빈도를 지키는 핵심 전제

## 안전한 주간 증량 기준

- 전통적 "주 10% 룰"보다 **ACWR(급성:만성 부하비 = 이번주 볼륨 ÷ 최근4주 평균 볼륨)**이 더 근거있는 지표: **0.8~1.3이 안전 구간**, 1.3~1.5 주의, 1.5 초과 고위험
- 롱런 등 단일 세션 거리는 **최근 30일 최장거리 대비 +10% 이내**로 증가
- **3~4주마다 볼륨 20~30% 감소하는 디로드(cutback) 주**를 넣는다

### ACWR 계산 방법 (가민에 직접 없음 — 직접 계산)

`get_training_load_trend`는 이름과 달리 실제로는 vo2max만 반환하고 CTL/ATL/ACWR을 주지 않는 것으로 확인됨(2026-07-09). 대신 아래처럼 직접 계산한다:

1. `get_activities_by_date`(running, 최근 8~9주)로 활동 목록을 가져와 **월요일 시작 ISO 주** 단위로 거리(km) 합산
2. 이번 주(acute) = 이번 주 합산 거리(진행중이면 지금까지 실적치, 또는 이번 주 계획된 총 볼륨). **"이번 주 계획된 총 볼륨"은 반드시 "주간 마일리지/시간 요약"의 "이번 주 계획 합계"와 같은 수치를 써야 한다** — 가민에 실제로 스케줄된 7일 기준이므로 수동 조정(예: 이지런→NSM-M)이 있으면 자동 반영됨. 페이즈 표의 대략적 목표(예: "~25km")로 대체하지 말 것(2026-07-09에 이 불일치를 발견해 수정함 — 회복주 목표 25km와 실제 스케줄 32.7km가 달랐던 사례).
3. 만성(chronic) = 바로 이전 4주 합산 거리의 평균
4. `ACWR = acute / chronic`. 0.8~1.3 안전(초록), 1.3~1.5 주의(황), 1.5+ 고위험(빨강). 실제 스케줄 기준으로 계산했는데도 0.8 미만이면(의도된 디로드) 경고 아님(대시보드에 "계획, 진행중"으로 별도 표기)
5. 참고: 2026-07-09 기준 계산 결과 — 6/8주 1.37, 6/15주 1.47, 6/22주 1.47(15K/30K pace·LT 인터벌이 이어지던 구간, 주의 구간까지 상승), 6/29주 1.07(안전), 7/6주 계획 0.86(실제 스케줄 32.7km 기준, 안전 구간 안쪽). 대시보드 "훈련 부하(ACWR)" 섹션에 이 방식으로 매번 갱신.

- **"이번주 일정" 바로 아래에 "주간 날씨" 섹션도 표시**한다 — 월~일 7일 타일, 각 날짜의 최저/최고기온·최대강수확률·간단 설명(정오 기준)을 보여준다. `wttr.in`은 오늘 포함 3일치(today+2)만 주므로:
  - 지난 날짜(오늘 이전)는 `.no-data` 스타일로 "지난 날" 표시

  - 오늘 타일은 `.ww-tile.is-today`로 파란 박스(다른 today 요소와 동일한 `--today-box`) 표시
  - 예보 가능한 날 중 롱런/sub-threshold 등 중요 세션이 있는 날의 날씨가 특이하면(고온·고강수확률 등) 한 줄 코멘트로 안내(예: 무더위 대비 이른 출발, 우천 대비 등)
- 날씨는 매일 갱신, 위치가 바뀌면 이 섹션의 지역명을 업데이트할 것

## 동적 주간 조정 규칙 (전날 시행/미시행에 따라 계속 갱신)

이번 주 계획은 한 번 정해지면 고정이 아니라 **매일 전날 이전의 실제 수행 결과를 반영해 남은 요일을 조정**한다. (2026-07-17 변경: "이번 주"는 이제 달력 주 단위가 아니라 "훈련 방법론"의 하드-이지 2일 연속 주기 기준으로 해석한다 — 아래 "남은 요일"은 실질적으로 "다음 하드 세션 전까지 남은 이지런 슬롯"을 의미하며, 하드 세션끼리 최소 하루 간격은 주기 설계상 항상 자동으로 충족된다.)

1. **sub-threshold(NSM-S/M/L) 또는 롱런이 FAIL(미실시 포함) 등급**을 받았다면 → 이번 주 남은 요일 중 이미 REST로 잡힌 날이 있으면 그 자리에 같은 세션을 재배치한다. 단, 재배치해도 (a) 하드 세션끼리 최소 하루는 띄우고 (b) 이번 주 sub-threshold 총 세션수가 원래 상한(3, 회복 저조시 2)을 넘지 않아야 한다. 재배치할 REST 슬롯이 없으면 그냥 넘어간다 — 볼륨을 억지로 채우지 않는다(ACWR 관리가 우선).
2. **이지런/회복런 미실시**는 재배치하지 않는다. 그냥 볼륨 손실로 남기고 다음 주 계획에서 자연히 반영한다.
3. **연속 2일 이상 미실시 또는 컨디션 저하(HRV LOW·수면부족)가 겹치면** 이번 주 남은 sub-threshold 세션 중 하나를 이지런으로 자동 강등한다.
4. 조정 시 `unschedule_workout`/`schedule_workout`으로 가민 캘린더를 갱신하고, plan.md 실행 로그에 조정 사유를 기록한다.

## 수동 조정 로그 규칙

사용자가 채팅으로 직접 "오늘 계획을 바꿔줘"라고 요청하면(자동 판단이 아니라 사용자 지시), 아래처럼 구분해서 처리한다:

1. 요청대로 `unschedule_workout`/`schedule_workout`으로 즉시 반영하고 대시보드도 그 자리에서 갱신한다.
2. plan.md 실행 로그와 대시보드(오늘 카드 라벨/노트)에 **"사용자 수동 조정"**임을 명시하고, 원래 예정이었던 워크아웃과 변경 사유(있다면)를 함께 남긴다.
3. **수행률 채점 기준은 항상 "최종적으로 스케줄된 워크아웃"** — 수동 조정 이후의 워크아웃을 기준으로 삼는다. 원래 자동으로 잡혔던 워크아웃과 달라졌다고 해서 미실시나 이상 신호로 취급하지 않는다.

## 세션 평가 등급 (양호/주의/경고/FAIL) — runner.joseons.com 기준 채택 (2026-07-09)

기존에는 %로 점수를 냈지만, 사용자 요청으로 **HR(심박) 기반 등급제**로 전환했다. 지난 날짜의 계획 대비 실제 수행을 아래 규칙으로 등급화한다. **휴식일과 "계획 이전"(자동화 시작 전) 날짜는 평가 대상에서 제외**한다.

**기준값**: MaxHR 190bpm / LTHR 165bpm / RestingHR 42bpm (사용자 확인)

**절대 기준(계산된 bpm)**:
- Easy 상한 = MaxHR×70% = **133bpm**
- Easy 경고 = Easy상한+7bpm = **140bpm**
- Easy 실패 = Easy상한+14bpm = **147bpm**
- Soft Ceiling(개별 인터벌 랩 최고HR 마지노선) = LTHR+2bpm = **167bpm**
- 역치 마지노선(절대) = LTHR = **165bpm**

**세션별 인터벌 워크 랩 목표 최고HR** (LTHR 165 기준):
| 세션 | 타깃존(%LTHR) | 타깃존(bpm) | 양호 판정(하한-3bpm까지) |
|---|---|---|---|
| NSM-S (3min) | 94~99% | 155~163 | 152bpm 이상 ~ 163bpm 이하 |
| NSM-M (6min) | 92~97% | 152~160 | 149bpm 이상 ~ 160bpm 이하 |
| NSM-L (10min) | 90~95% | 149~157 | 146bpm 이상 ~ 157bpm 이하 |

1. `get_activities_fordate(날짜)`로 그 날 러닝 액티비티를 찾는다. 없으면 **FAIL(미실시)**.
2. 워크아웃 종류에 따라 다르게 등급 판정:
   - **이지런/회복런/롱런(연속형)**
     - `volume_ratio = 실제값 / 목표값`(이지런은 duration_seconds, 롱런·회복런은 distance_meters). `volume_ratio < 0.7`이면 최대 **주의**로 캡.
     - 그 외에는 평균 HR(`avg_hr_bpm`)로 판정: **133bpm 미만 → 양호**, 133~139 → **주의**, 140~146 → **경고**, 147bpm 이상 → **FAIL**
   - **sub-threshold(NSM-S/M/L)**
     - `get_activity_splits(activity_id)`에서 `intensity_type == "ACTIVE"`인 랩만 추출(WARMUP/RECOVERY/COOLDOWN 제외) — `get_activity_split_summaries`나 `get_activity_typed_splits`는 랩별 세분화에 부적합하니 쓰지 않는다.
     - **전역 FAIL 체크(우선)**: ACTIVE 랩 중 하나라도 `max_hr_bpm` > 167(Soft Ceiling) → **세션 FAIL**. 활동 전체 HR 시계열에서 165bpm(LTHR) 초과 비율이 5%를 넘으면 → **세션 FAIL**, 5% 이하지만 1회라도 초과하면 → 최소 **경고**.
     - 전역 FAIL이 아니면 랩별 판정: 각 ACTIVE 랩의 `max_hr_bpm`이 [해당 세션 타깃존 하한-3bpm, 상한] 안이면 그 랩 양호, 벗어나면 그 랩 주의.
     - 반복수 미완주(ACTIVE 랩 수 < 계획 반복수)면 최대 **주의**로 캡.
     - **세션 종합 등급 = 위 항목 중 가장 나쁜 등급** (FAIL > 경고 > 주의 > 양호 순으로 나쁨)
3. 색상 매핑: **양호=success(초록) / 주의·경고=warn(황, 라벨 텍스트로 구분) / FAIL=miss(빨강)**
4. 주간 요약은 평가 대상 일자들의 등급 중 최빈값 또는 가장 나쁜 등급 중 하나를 대표로 표시(대시보드 구현 시 결정, 매주 방식 통일 유지)

## 주간 마일리지/시간 요약 ("이번주 일정" 상단 표시)

"이번주 일정" 섹션 상단에 두 박스로 표시한다:

1. **실제 누적(월~오늘)**: 이번 주 월요일부터 오늘까지 `get_activities_fordate`로 확인되는 실제 러닝 활동의 `distance_meters`/`duration_seconds` 합계(km, hh:mm으로 변환). 자동화 이전 날짜(계획 없던 날)의 실제 러닝도 포함한다 — 실제로 뛴 거리/시간이므로.
2. **이번 주 계획 합계**: 이번 주(월~일) 가민에 스케줄된 7일치 워크아웃 기준 합계.
   - 거리 목표가 명시된 워크아웃(롱런/회복런 등)은 그 값을 그대로 사용
   - 시간 목표만 있는 워크아웃(이지런, NSM-S/M/L)은 **페이스 존 중간값**으로 거리를 역산해서 더한다(예: 이지런 40min → 이지 페이스존 5:35–6:05 중간값 5:50/km로 40÷5:50≈6.9km). sub-threshold는 반복 구간 거리(반복시간×페이스) + 워밍업/쿨다운은 이지 페이스 10분씩으로 가정해 더한다.
   - 계획에 없던 날(자동화 이전 등)은 0으로 취급 — "계획" 수치이므로 실제로 스케줄되지 않은 날은 포함하지 않는다.
   - 추정이 섞여 있으므로 박스 안에 "* 시간 기반 세션은 페이스 존 중간값으로 거리 추정" 각주를 항상 표시한다.
3. 표기 형식(사용자 지정): 거리는 **`7.7km`**처럼 소수 1자리+단위 붙여쓰기, 시간은 **`3h7m`**처럼 시:분을 콜론 없이 h/m로 표기(시간이 0이어도 `0h41m`처럼 항상 h를 표시). 대시보드 기존 stat 스타일(`.week-summary`)을 사용한다.
