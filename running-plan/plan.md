## 훈련 방법론: NSM (Norwegian Singles Method)

- 주간 구성: 이지런 약 75% + sub-threshold 약 25%. 여유 있을 때는 **sub-threshold 세션 3회(short+mid+long, 매주 세 포맷 모두 함께) + 롱런 1회 = 워크아웃 4회**, 나머지는 완전 이지런/휴식
- **포맷은 단계별로 교체하는 게 아니라 매주 3개 다 돌리는 것이 원칙.** 각 포맷의 역할이 다름 — short(3~4min)는 역치 부근 회전율/스피드, mid(6~8min)는 중간 지속시간, long(10~12min)은 지속적 유산소 압박(레이스 특이성 가장 높음, 10K/HM 완주력과 직결)
- **세션이 3개가 아니라 2개만 가능할 때(회복 저조 등)는 short + long을 유지하고 mid를 뺀다** — short/long이 스펙트럼 양끝을 담당해 둘만으로도 폭넓은 자극이 되고 mid가 가장 먼저 생략 가능
- 퀄리티(워밍업/쿨다운 제외) 총 시간은 **주간 총 볼륨의 20~25%가 기본**, 볼륨이 크거나 훈련 연차가 쌓이면 **최대 25~30%까지 확장 가능**
- 인터벌은 **시간 기준**: `3min x 8~10rep` / `6min x 4~5rep` / `12min x 2~3rep`. **반복 사이 60초 휴식은 조깅이 아니라 도보(워킹)/완전휴식** (짧은 60초에서는 조깅이 회복에 큰 도움 없이 부하만 늘림)
- VO2max/전력 인터벌은 최소화, 레이스 임박 구간에서만 목표 페이스 감각용으로 짧게 포함
- 이지런은 진짜 이지(HR 캡)로 철저히 통제 — sub-threshold 세션의 질과 빈도를 지키는 핵심 전제

## 안전한 주간 증량 기준

- 전통적 "주 10% 룰"보다 **ACWR(급성:만성 부하비 = 이번주 볼륨 ÷ 최근4주 평균 볼륨)**이 더 근거있는 지표: **0.8~1.3이 안전 구간**, 1.3~1.5 주의, 1.5 초과 고위험
- 롱런 등 단일 세션 거리는 **최근 30일 최장거리 대비 +10% 이내**로 증가
- **3~4주마다 볼륨 20~30% 감소하는 디로드(cutback) 주**를 넣는다

### ACWR 계산 방법 (가민에 직접 없음 — 직접 계산)

`get_training_load_trend`는 이름과 달리 실제로는 vo2max만 반환하고 CTL/ATL/ACWR을 주지 않는 것으로 확인됨(2026-07-09). 대신 아래처럼 직접 계산한다:

1. `get_activities_by_date`(running, 최근 8~9주)로 활동 목록을 가져와 **월요일 시작 ISO 주** 단위로 거리(km) 합산
2. 이번 주(acute) = 이번 주 합산 거리(진행중이면 지금까지 실적치, 또는 이번 주 계획된 총 볼륨)
3. 만성(chronic) = 바로 이전 4주 합산 거리의 평균
4. `ACWR = acute / chronic`. 0.8~1.3 안전(초록), 1.3~1.5 주의(황), 1.5+ 고위험(빨강). 디로드 주라 계획상 낮게 잡은 경우 0.8 미만은 의도된 것이니 경고 아님(대시보드에 "계획, 진행중"으로 별도 표기)
5. 참고: 2026-07-09 기준 계산 결과 — 6/8주 1.37, 6/15주 1.47, 6/22주 1.47(15K/30K pace·LT 인터벌이 이어지던 구간, 주의 구간까지 상승), 6/29주 1.07(안전), 7/6주 계획 0.66(의도된 디로드). 대시보드 "훈련 부하(ACWR)" 섹션에 이 방식으로 매번 갱신.

## 날씨 연동

- 러닝 지역: **서울** (사용자 확인, 2026-07-09)
- 가민 MCP에는 예보 도구가 없음 — `curl -s "https://wttr.in/Seoul?format=j1"`로 JSON을 받아 오늘/내일 `weather[].hourly[]`에서 시간대별 `tempC`, `humidity`, `chanceofrain`을 추출해 사용
- 대시보드 "오늘 날씨" 섹션에 오늘 남은 시간대(예: 09/12/15/18/21시) 온도·습도·강수확률을 타일로 표시하고, 강수확률이 가장 낮은 시간대를 강조(`is-best` 스타일) + 한 줄 코멘트(고온다습 시 페이스 여유·수분 보충 권장 등)
- 날씨는 매일 갱신, 위치가 바뀌면 이 섹션의 지역명을 업데이트할 것

## 동적 주간 조정 규칙 (전날 시행/미시행에 따라 계속 갱신)

이번 주 계획은 한 번 정해지면 고정이 아니라 **매일 전날 이전의 실제 수행 결과를 반영해 남은 요일을 조정**한다:

1. **sub-threshold(NSM-S/M/L) 또는 롱런이 미실시(0%) 또는 저조(<50%)**했다면 → 이번 주 남은 요일 중 이미 REST로 잡힌 날이 있으면 그 자리에 같은 세션을 재배치한다. 단, 재배치해도 (a) 하드 세션끼리 최소 하루는 띄우고 (b) 이번 주 sub-threshold 총 세션수가 원래 상한(3, 회복 저조시 2)을 넘지 않아야 한다. 재배치할 REST 슬롯이 없으면 그냥 넘어간다 — 볼륨을 억지로 채우지 않는다(ACWR 관리가 우선).
2. **이지런/회복런 미실시**는 재배치하지 않는다. 그냥 볼륨 손실로 남기고 다음 주 계획에서 자연히 반영한다.
3. **연속 2일 이상 미실시 또는 컨디션 저하(HRV LOW·수면부족)가 겹치면** 이번 주 남은 sub-threshold 세션 중 하나를 이지런으로 자동 강등한다.
4. 조정 시 `unschedule_workout`/`schedule_workout`으로 가민 캘린더를 갱신하고, plan.md 실행 로그에 조정 사유를 기록한다.

## 수동 조정 로그 규칙

사용자가 채팅으로 직접 "오늘 계획을 바꿔줘"라고 요청하면(자동 판단이 아니라 사용자 지시), 아래처럼 구분해서 처리한다:

1. 요청대로 `unschedule_workout`/`schedule_workout`으로 즉시 반영하고 대시보드도 그 자리에서 갱신한다.
2. plan.md 실행 로그와 대시보드(오늘 카드 라벨/노트)에 **"사용자 수동 조정"**임을 명시하고, 원래 예정이었던 워크아웃과 변경 사유(있다면)를 함께 남긴다.
3. **수행률 채점 기준은 항상 "최종적으로 스케줄된 워크아웃"** — 수동 조정 이후의 워크아웃을 기준으로 삼는다. 원래 자동으로 잡혔던 워크아웃과 달라졌다고 해서 미실시나 이상 신호로 취급하지 않는다.
4. 다음 날 이후의 동적 주간 조정 판단(위 섹션)에서도 이 날은 "사용자가 의도적으로 바꾼 날"로 취급 — 컨디션 저하로 인한 자동 강등 사유에 포함시키지 않는다(사용자 판단을 존중, 억지로 되돌리지 않음).

## 수행률(%) 평가 방법

지난 날짜의 계획 대비 실제 수행을 아래 규칙으로 점수화한다. **휴식일과 "계획 이전"(자동화 시작 전) 날짜는 평가 대상에서 제외**하고, 주간 평균도 이 날들을 뺀 값으로 낸다.

1. `get_activities_fordate(날짜)`로 그 날 러닝 액티비티를 찾는다. 없으면 **0%(미실시)**.
2. 워크아웃 종류에 따라 다르게 채점:
   - **이지런/회복런/롱런(연속형, 시간 또는 거리 목표 + HR 상한)**
     - `volume_ratio = min(실제값 / 목표값, 1.0)` — 이지런은 duration_seconds, 롱런·회복런은 distance_meters 기준
     - HR 판정: `avg_hr_bpm`이 상한 이하면 감점 없음. 상한 초과 시 초과폭에 따라 감점(1~5bpm 초과 -5%p, 5~10bpm -15%p, 10bpm+ -30%p) — 이지런의 목적 자체가 "진짜 이지"이므로 초과는 감점 대상
     - `점수 = round(volume_ratio*100) - HR감점`, 0~100으로 clamp
   - **sub-threshold(NSM short/mid/long)**
     - `get_activity_split_summaries(activity_id)`에서 `splitType == "INTERVAL_ACTIVE"`인 항목을 찾는다(실측 확인: 8x3min 세션에서 noOfSplits=8, averageSpeed로 페이스 역산 가능)
     - `reps_ratio = min(noOfSplits / 계획 반복수, 1.0)`
     - `avg_pace_sec_per_km = 1000 / averageSpeed`를 계획 페이스 밴드와 비교 → 밴드 안이면 pace_score=100, 밴드 밖이면 5초/km 벗어날 때마다 -10%p
     - `점수 = round(0.5*reps_ratio*100 + 0.5*pace_score)`
3. 상태 색상: **90%+ success(초록) / 70~89% warn(황) / 70% 미만 miss(빨강)**
4. 주간 요약 % = 평가 대상 일자 점수의 평균

## 주간 마일리지/시간 요약 ("이번주 일정" 상단 표시)

"이번주 일정" 섹션 상단에 두 박스로 표시한다:

1. **실제 누적(월~오늘)**: 이번 주 월요일부터 오늘까지 `get_activities_fordate`로 확인되는 실제 러닝 활동의 `distance_meters`/`duration_seconds` 합계(km, hh:mm으로 변환). 자동화 이전 날짜(계획 없던 날)의 실제 러닝도 포함한다 — 실제로 뛴 거리/시간이므로.
2. **이번 주 계획 합계**: 이번 주(월~일) 가민에 스케줄된 7일치 워크아웃 기준 합계.
   - 거리 목표가 명시된 워크아웃(롱런/회복런 등)은 그 값을 그대로 사용
   - 시간 목표만 있는 워크아웃(이지런, NSM-S/M/L)은 **페이스 존 중간값**으로 거리를 역산해서 더한다(예: 이지런 40min → 이지 페이스존 5:35–6:05 중간값 5:50/km로 40÷5:50≈6.9km). sub-threshold는 반복 구간 거리(반복시간×페이스) + 워밍업/쿨다운은 이지 페이스 10분씩으로 가정해 더한다.
   - 계획에 없던 날(자동화 이전 등)은 0으로 취급 — "계획" 수치이므로 실제로 스케줄되지 않은 날은 포함하지 않는다.
   - 추정이 섞여 있으므로 박스 안에 "* 시간 기반 세션은 페이스 존 중간값으로 거리 추정" 각주를 항상 표시한다.
